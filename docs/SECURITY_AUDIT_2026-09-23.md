## 项目结构与审查计划

项目是 Manifest V3 浏览器扩展。`extension/manifest.json` 声明 service worker、`storage` 和 HTTP/HTTPS 主机权限；`background.js` 负责受信设置/存储、发送者校验、请求并发与取消、缓存和 Jev API 调用；`blocks.js` 从页面提取可读区域描述并维护隔离世界内的 DOM 所有权；`content.js` 应用规则和自动判断；`manual.js`、`preview.js`、`console.js` 提供手动选择、预览及网页操作台；弹窗和设置页承担受信设置界面。可选 AI 请求包含可读文字、图片/嵌入媒体提示、结构线索及已去查询参数的链接路径；手动规则保存在本机。

执行顺序为：先核对版本/商店/隐私台账和当前工作区边界；再围绕隐私采集、页面可伪造标记、取消生命周期与 DOM 标记所有权进行复现；为每个确认问题先建立失败测试，再修复根因；最后运行全量测试、语法、locale JSON、依赖审计和差异检查，并让只读审核者按需求完整性、逻辑、边界、质量、测试、运行结果六个维度复核。

## 本轮新增并已验证的问题

### 1. CSS 全透明区域会进入 AI 载荷 `[P1，隐私边界]`

**位置与根因：**`extension/blocks.js` 的 `excluded()` / `readableCopy()`。旧过滤器覆盖编辑区域、`display:none`、`visibility:hidden/collapse` 等情形，却没有把透明度为零的祖先、零透明度滤镜和 `content-visibility:hidden` 作为不可读内容处理。后果是用户看不到的页面文字仍可能进入分类或拆分请求。

**修复前证据：**LinkeDOM 样例得到 `{"collected":["normal","opacity"],"markedText":"","opacityText":"PUBLIC HIDDEN_SECRET"}`；进一步通过 fetch stub 实际调用分类和拆分路径，捕获到的请求 body 含隐藏哨兵文本，而 `visibility:hidden` 对照样本被过滤。没有发出真实网络请求。

**修改与原因：**对节点及祖先的 computed `opacity <= 0`、`filter: opacity(0)`/`opacity(0%)` 和 `content-visibility:hidden` 做统一排除，使分类和拆分共用同一可读 DOM 根路径；不只过滤文本，链接和图片描述同样从过滤后的副本提取。修复从可见性判定根因入手，避免单独在某一 API 调用点打补丁。

**复验：**`blocks.test.mjs` 与 `content.test.mjs` 覆盖透明度、滤镜、`content-visibility` 以及分类请求负载；当前全量测试 219/219 通过。

**结论：**已修复并由请求载荷测试确认隐藏哨兵不再外发。`clip-path` 裁切、屏幕外区域、遮挡和其他复杂视觉效果未穷举，见遗留风险。

### 2. 网页可伪造 `data-jev-ui` 以绕过内容与规则处理 `[P2，完整性/可用性]`

**位置与根因：**`extension/blocks.js`、`manual.js`、`preview.js`、`console.js` 及旧 `layout-snapshot.js`。将普通 DOM 属性当作扩展 UI 的真实性凭证，使页面能给自己的节点添加该属性，从而让采集、保存规则、选区点击或操作台挂载逻辑把页面内容误判为扩展 UI。

**修复前证据：**在 LinkeDOM 页面样例给普通文章节点添加 `data-jev-ui` 后，`collect()` 不再返回该节点、`describe()` 返回空描述，手动规则匹配数为 0；预览候选和控制台挂载用例也能复现受影响路径。

**修改与原因：**在内容脚本隔离世界中登记真实 UI 根节点和角色，提供 `registerUi/unregisterUi/isUi/containsUi/findUi`；业务逻辑只信任私有登记，DOM 属性仅作样式/诊断标记。预览和操作台销毁时注销登记；手动选择与旧快照也改用私有所有权判断。`layout-snapshot.js` 当前不在 manifest 活跃内容脚本清单中，仍一并修正以避免旧路径重新启用后恢复漏洞。

**复验：**`blocks.test.mjs`、`manual.test.mjs`、`preview.test.mjs`、`console.test.mjs`、`layout-snapshot.test.mjs` 分别覆盖伪造标记不能屏蔽页面节点或扩展 UI；当前全量测试 219/219 通过。

**结论：**已修复。页面可写属性不再决定隔离世界中的 UI 归属。

### 3. 请求取消被误报为网络故障并可能暂停后续扫描 `[P3，可恢复性]`

**位置与根因：**`extension/classifier.mjs`、`background.js`、`content.js`、`preview.js`。fetch、读取 JSON、后台批量任务和内容脚本各自把原生 `AbortError` 混入连接错误、无效 JSON 或普通逐块失败；清除/更换密钥等有意撤销可能形成错误提示或暂停状态。

**修复前证据：**用已取消信号调用 classifier，fetch 调用次数为 0，但返回“无法连接 Jev 服务”；让 `response.json()` 抛出 AbortError 则被报告成无效 JSON。后台清除密钥时的 fetch stub 显示取消被计入块错误，内容脚本将该错误路径当作终止暂停。所有复现均为本地 stub。

**修改与原因：**统一把原生 abort 和已撤销的 signal 规范为结构化 `code: "canceled"`，贯穿响应读取、后台 job、内容重试和拆分 UI；取消既不进入错误缓存，也不被当作普通网络失败；重置该块状态以便后续条件允许时继续尝试。

**复验：**`backend.test.mjs` 覆盖 fetch/响应读取 AbortError、密钥清除和排队取消；`content.test.mjs` 验证取消后保持可重试；当前全量测试 219/219 通过。

**结论：**已修复，取消继续按控制流处理而非故障。

### 4. 清理隐藏标记会删除页面原有属性 `[P2，页面 DOM 完整性]`

**位置与根因：**`extension/blocks.js` 的 `setHidden()`。旧逻辑只按属性名记录扩展使用过该标记，关闭时不区分该属性是页面预先设置、扩展添加，还是页面在隐藏期间改写。

**修复前证据：**新增失败测试后，元素原有 `data-jev-zhihu-hidden="page-owned"`，调用 `setHidden(..., false)` 得到 `null` 而非原值；测试对 `data-jev-manual-hidden` 和 `data-jev-preview-hide` 也覆盖同样契约。第一次修复还触发既有 `scroll-style rescans never remove unchanged hidden attributes` 回归：页面移除扩展标记后，下一轮重扫没有重新施加标记。

**修改与原因：**每节点改为按属性保存 `{added, value}` 所有权记录。仅删除扩展最初添加且当前值仍与扩展值相同的属性；预先存在或被页面改写的值保留。若页面删除了扩展自身的活动标记，下一次启用会重施标记，但不会覆盖页面改写的值。这同时守住页面 DOM 完整性和扩展重扫契约。

**复验：**修正后的 `blocks.test.mjs` 25/25、当前 `preview.test.mjs` 41/41 通过；首版所有权逻辑曾被旧的滚动重扫用例抓到回归，修正后重复全量测试通过。最终主线程与独立只读复审分别对最新 diff 执行全量测试，均为 219/219。

**结论：**已修复。红测证明原缺陷，初版回归被既有滚动扫描测试捕获，收敛后的实现通过定向与全量复验。

### 5. 预览临时标记覆盖并删除页面原有属性 `[P2，页面 DOM 完整性]`

**位置与根因：**`extension/preview.js` 的 `syncCandidates()`、`selectKnown()`、`focus()`、`offerGroup()` 和清理路径。候选、选中、焦点、分组标记直接写入共享页面 DOM；网页原本设置同名属性时，扩展会覆盖其值并在取消/切换时删除。

**修复前证据：**新增集成回归在直接 `setAttribute/removeAttribute` 版本先红：页面预置 `data-jev-candidate="page-candidate"` 等值，启动选择、焦点及分组建议后取消，断言实际得到 `null`，预期原始页面值。最终用例验证扩展不再新增候选属性，页面预置值和页面在操作期间写入的新值均保持不变。

**修改与原因：**最终方案不再向页面节点写入候选、选中、焦点或分组属性；业务状态仅留在隔离世界的 `candidates/selected/focusNode/groupOffer` 中，候选框、焦点和分组建议全部在闭合扩展遮罩层绘制。对应的共享页面 CSS 选择器已删除。首版可逆属性方案虽能还原旧值，独立复核仍确认页面 CSS/MutationObserver 可对临时标记作出不可撤销响应，因此本次从根因移除写入，而不只补偿恢复。

**复验：**`preview.test.mjs` 新用例验证不会新增共享属性、页面原值和活动期改写值均保持不变、候选/选中/焦点/分组状态仍由闭合遮罩层正确绘制。定向测试及全量 219/219 通过。

**结论：**已修复。预览状态以隔离世界变量为唯一业务事实，不再产生页面可观察的临时属性副作用。

### 6. 孤儿 CSS 属性规则会影响页面同名属性 `[P3，低风险样式副作用]`

**位置与根因：**`extension/content.css` 曾有 `[data-jev-hover]` 和 `[data-jev-awaiting]` 两条规则，而 `extension/` 中不存在生产 setter 或读取者。浏览器会将扩展注入的样式应用到任何匹配的页面元素；页面若已有或主动设置同名属性，会得到扩展定义的 outline、透明度或 pointer-events。

**验证与限制：**独立审核者通过全仓搜索确认两条规则无生产消费者/设置者；CSS selector 与声明表明属性命中即应用样式。这是静态可证的副作用路径；本轮候选未做真实浏览器端到端复现，因此不把其写成已浏览器验证的运行缺陷。

**修改与原因：**删除两条无使用者的 CSS 规则，减少共享页面 DOM 命名空间碰撞面，不保留死代码。

**复验与结论：**`rg` 确认源码不再含这两个 selector 或 setter；全量 219/219 通过，`git diff --check` 通过。该低风险候选影响已清理。
